2D/3D 视觉效果图景：three.js、Remotion、Blender 与 Unity

想做出好看的 2D/3D 视觉效果，可选项散落在网页、视频、游戏三个领域。这篇笔记先把整张地图画出来，再逐个拆解 three.js、Remotion、Blender、Unity 四个代表性框架的定位与核心概念，最后给出选型对照和学习路径。

更新 2026-10-30记录 2026-10-30

网页上的 3D 展示、一段数据驱动的动画视频、一个 2D 或 3D 游戏——看起来是三件不同的事，但底层其实是同一套知识：用数学描述形状，用光照模型计算颜色，按时间轴驱动变化，最后由渲染器把这一切变成像素。差别只在于"每帧渲染要花多少时间"和"观众能不能干预"。

先建立地图：两条渲染管线

所有视觉创作工具都能放进这张地图里，判断标准就一个：渲染一帧允许花多长时间。

管线特征典型输出代表工具
实时渲染每帧预算约 16ms（60fps），牺牲画质换速度，光照用近似算法网页、游戏、互动装置、XRthree.js、Babylon.js、Unity、Unreal、Godot
离线渲染一帧可以算几秒到几小时，用物理精确的光线追踪影视动画、广告、片头Blender (Cycles)、Arnold、RenderMan
程序化视频介于两者之间：逐帧截取浏览器/引擎画面再合成视频，帧确定性数据动画、节目包装、自动化视频Remotion、Motion Canvas

第二个判断标准是素材从哪来：美术资产（模型、贴图、绑定）主要靠 DCC 工具（Blender、Maya、C4D）制作，再通过 glTF/FBX 等格式流入渲染端；而 three.js、Remotion 这类代码驱动工具的长处是让程序参数直接决定视觉。两条路通常是组合使用的。

three.js：网页里的 3D 世界

three.js 是对 WebGL（以及新一代 WebGPU）的场景图封装，是网页 3D 事实上的标准。它不提供游戏逻辑，只负责"把 3D 场景画出来"这一件事，因此格外适合做产品展示、数据可视化和创意网页。

核心对象模型

  • Scene / Camera / Renderer：三件套是每个程序的起点——场景装物体，相机定视角，渲染器逐帧把场景画到 canvas 上。
  • Mesh = Geometry + Material：几何体描述形状（Box、Sphere，或加载 glTF 模型），材质描述表面（颜色、金属度、粗糙度、贴图）。
  • Light：环境光、方向光、点光源；实时渲染的光照是近似算法（PBR 着色模型），和离线渲染的物理精确路径追踪不同。
  • 动画循环：用 requestAnimationFrame 驱动，每帧更新物体状态后重新渲染。
import * as THREE from 'three';

const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(75, innerWidth / innerHeight, 0.1, 100);
camera.position.z = 5;

const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(innerWidth, innerHeight);
document.body.appendChild(renderer.domElement);

const cube = new THREE.Mesh(
  new THREE.BoxGeometry(1, 1, 1),
  new THREE.MeshStandardMaterial({ color: 0x4a9d6e, roughness: 0.4 })
);
scene.add(cube);
scene.add(new THREE.AmbientLight(0xffffff, 0.5));
const key = new THREE.DirectionalLight(0xffffff, 1.5);
key.position.set(3, 4, 5);
scene.add(key);

function animate(t) {
  cube.rotation.y = t / 1000;
  renderer.render(scene, camera);
  requestAnimationFrame(animate);
}
requestAnimationFrame(animate);

生态与进阶

  • React Three Fiber：把 three.js 变成 React 组件，声明式搭场景，配 drei 工具库（相机控制、加载器、环境贴图开箱即用）。
  • 后期处理：泛光、景深、色调映射，通过 EffectComposer 叠加，网页 3D 的"高级感"一半来自这里。
  • TSL / WebGPU：three.js 正在向 WebGPU 迁移，节点式着色语言 TSL 让自定义着色器可以同时编译到 WebGL 和 WebGPU。
  • 同赛道替代品：Babylon.js（更全家桶，内置物理与 GUI）、<model-viewer>（零代码展示 glTF 产品模型）。

Remotion：用 React 写视频

Remotion 的核心洞见是：视频就是"以帧号为参数的纯函数"——第 n 帧画面 = f(n)，没有任何隐藏状态。这让它天然适合程序化生成：参数化模板、批量产出、AI 流水线接入都很顺。

核心概念

  • Composition：一段视频的声明，定义宽高、帧率、时长和入口组件。
  • useCurrentFrame()：拿到当前帧号，一切动画都从它推导，保证任意一帧可以独立重算、结果一致。
  • interpolate / spring：帧号到数值的插值和物理弹簧动画，代替传统时间轴。
  • Sequence：把组件按时间排列，相当于图层 + 时间轴的代码版。
import { useCurrentFrame, interpolate, spring } from 'remotion';

const Title: React.FC = () => {
  const frame = useCurrentFrame();
  const scale = spring({ frame, fps: 30, config: { damping: 12 } });
  const opacity = interpolate(frame, [10, 30], [0, 1], {
    extrapolateRight: 'clamp',
  });
  return <h1 style={{ transform: `scale(${scale})`, opacity }}>Hello</h1>;
};

渲染管线

渲染时 Remotion 用 headless Chrome 打开页面，按帧号逐帧截图，再交给 ffmpeg 合成 mp4。这就是"帧确定性"的价值：可以分布式并行渲染任意帧。局限也在这里——它是 2D/网页技术栈，做不了影视级 3D，但可以嵌 three.js 场景把 3D 内容烘进视频。典型用途：数据新闻动画、课程/讲座视频、GitHub 年报式个人化视频、批量生成的短视频模板。

Blender：开源 3D 全流程

Blender 不是渲染库，而是完整的 3D 内容创作软件：建模、雕刻、材质、灯光、绑定、动画、合成、剪辑全在一个应用里，且完全免费开源。它在管线里的角色是美术资产的源头。

主要能力模块

  • 建模：多边形建模是基本功；雕塑模式做有机形体；几何节点（Geometry Nodes）用节点图程序化生成几何体，撒树、做城市、生成晶格结构效率极高。
  • 材质与灯光：基于节点的 PBR 着色器，物理正确。
  • 渲染器：Eevee 是实时光栅化（接近游戏引擎，交互预览快）；Cycles 是路径追踪离线渲染（物理精确，影视级画质，慢）。
  • 绑定与动画：骨骼、反向动力学、形状键、非线性动画。
  • Python (bpy)：整个 Blender 可被 Python 驱动，写脚本批量建模、自动化渲染农场、程序化生成资产。

在协作管线里的位置

  • 导出 glTF 给网页（three.js / Babylon.js）和移动端——这是 Blender 到实时管线的标准通道；
  • 导出 FBX/USD 给 Unity、Unreal；
  • 直接用 Cycles 渲染成片，或输出序列帧进 DaVinci/AE 合成。

对程序员最友好的切入方式往往是反过来的：先学"怎么把模型导进 three.js"，再逐步回溯学建模与材质。

Unity：实时引擎与游戏

Unity 是商业实时引擎，three.js 只管"画"，Unity 管"整个交互产品"：渲染、物理、输入、音频、UI、资源管理、跨平台打包（PC/主机/移动/WebGL/XR）。2D 和 3D 都是第一公民。

架构与工作流

  • GameObject / Component：场景中一切皆 GameObject，行为靠挂组件（Transform、Renderer、Collider、自定义 C# 脚本），组合优于继承的设计。
  • C# 脚本：生命周期由引擎回调（Start、Update、OnCollisionEnter 等），Update 每帧执行，相当于游戏版的动画循环。
  • 2D 工作流：Sprite、Tilemap、2D 物理引擎，像素游戏和横版游戏开箱即用。
  • 渲染管线：URP（通用，性能与画质均衡，移动端首选）与 HDRP（高端，电影级）；Shader Graph 用节点编辑器写着色器，不用手写 HLSL。
  • Timeline / Cinemachine：引擎内做镜头语言和实时过场，也常被用来拍"实时渲染电影"。
using UnityEngine;

public class Rotator : MonoBehaviour
{
    [SerializeField] private float speed = 90f;

    private void Update()
    {
        transform.Rotate(Vector3.up, speed * Time.deltaTime);
    }
}

同赛道对比：Unreal 画质上限更高（Nanite/Lumen）、主攻 3D 大型项目与影视虚拟制片；Godot 开源轻量、2D 体验极佳，适合独立游戏。三者在"个人系统学习"语境下选 Unity 或 Godot 起步都合理。

学习路径建议

  1. three.js 先行，建立渲染直觉：场景图、相机、材质、光照这套概念在所有 3D 工具里通用。官方文档的 "Fundamentals" 章节加 Bruno Simon 的 Three.js Journey 是公认最佳入门。目标：在网页里摆出一个有光影、可交互的场景。
  2. Remotion 快速出可见成果：会 React 就能上手，一两天做出一条参数化视频，正反馈最强。顺带理解"帧确定性"这一程序化视频的核心思想。
  3. Blender 补美术管线：从多边形建模开始，再学材质和烘焙；重点不是成为美术，而是理解资产如何生产并导出 glTF，与 three.js/Unity 打通。经典教程：Blender Guru 的甜甜圈系列。
  4. Unity 做完整交互项目：官方 Learn 路径（如 Junior Programmer）加一个小而完整的 2D 游戏再转 3D，把物理、输入、UI、打包全链路走一遍。

四个工具共同的地基是三块：线性代数（向量、矩阵、四元数——相机与变换的语言）、PBR 渲染原理（为什么金属度和粗糙度决定质感）、关键帧与缓动（一切动画的本质）。地基打牢后，换任何工具都只是换语法。
