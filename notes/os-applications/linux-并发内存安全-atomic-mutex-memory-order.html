原子变量底层原理

一篇很好的博客，深入剖析内存屏障

为什么不加保护地并发访问内存会出错

当我们修改内存时，例如 count++ 代码，这个操作并不是原子的，它包含几个步骤：

  1. 读取(load)：从内存中把变量 count 的值，加载到 CPU 的寄存器中；
  2. 计算(add)：在 CPU 寄存器里，对读取到的值执行 +1 运算；
  3. 写入(store)：把寄存器里计算后的新值，写回到内存的原位置。

这3个步骤可能分别是原子的，但是他们组合在一起就可能被打断。因为 CPU 的线程调度是抢占式的，而当多个线程并发操作同一块内存时，CPU 的线程切换，极有可能发生在非原子操作的步骤间隙。

并发访问内存的3大问题

  1. 竞态条件（Race Condition）：多个线程同时读写同一块内存，最终的执行结果依赖于 CPU 的调度顺序，而调度顺序是完全不可控的。
  2. 可见性问题（Visibility）：线程会优先把内存数据加载到自己独占的 CPU 缓存中进行读写，而非直接操作物理内存；其他线程看不到这个修改后的值。
  3. 有序性问题（Ordering）：为了提升执行效率，CPU 会对指令执行顺序做重排序（代码写的顺序 ≠ 实际 CPU 执行的顺序），单线程下重排序不会有问题，但多线程下，指令重排序会破坏线程之间的执行逻辑依赖；

原子变量的核心原理

相比普通变量，C++原子变量有如下两个基本特性：

  1. 原子变量的所有操作（fetch_add、store、load、compare_exchange_strong、exchange等）都具有原子性；
  2. 原子变量可以解决内存序问题，保证多个变量的可见性保持一定的一致性。

原子变量的根本原理在3个方面：

  1. 指令层面：单条指令替代多步复合操作。所有原子操作（fetch_add/CAS/exchange/store/load），最终都被编译成CPU 的单条指令，没有拆分步骤，CPU 执行单条指令时，不会在指令中间发生线程切换。
  2. 原子层面：硬件级锁保证独占访问。
    • 带 lock 前缀的指令（add/cmpxchg）：硬件锁总线 / 缓存，独占内存地址，其他线程无法访问；
    • 无 lock 但天生原子的指令（xchg/mov）：CPU 架构原生保证原子性，无需额外锁；
  3. 缓存层面：解决可见性问题。所有原子指令执行后，CPU 会通过 MESI 缓存一致性协议，自动将修改后的内存值同步到所有 CPU 核心的缓存中，确保其他线程读取时，能拿到最新值，彻底解决线程 A 改了，线程 B 看不到的可见性问题。

以 x86 架构为例，5条核心原子指令的汇编：

fetch_add:
lock add    dword ptr [counter32],0Ah

compare_exchange_strong:
mov         ecx,0Bh // 参数2
mov         eax,0Ah // 参数1
lock cmpxchg dword ptr [counter32],ecx

exchange:
mov         ecx,3 // 参数1
xchg        ecx,dword ptr [counter32]

store:
mov         eax,0Fh // 参数1
xchg        eax,dword ptr [counter32]

load:
mov         edx,dword ptr [counter32]

内存乱序问题

乱序有两种：

  1. 编译乱序：编译器根据目标平台的CPU特性，适当调整指令顺序，使得单个线程中的执行速度更快。
  2. CPU乱序：与 MISE 缓存协议与 Store Buffer 有关，我还没有完全理解。

内存乱序解决方法

  1. 关闭编译器优化，在实际项目中，基本不可能。
  2. 使用volatile关键字，保证编译器不会优化变量，变量每次读写都会从存储器完成。主要用在嵌入式开发场景。
  3. 使用操作系统提供的内存屏障机制，内存屏障也是std::memory_order的底层实现。内存屏障对CPU微指令的影响，本质上是间接操作Store Buffer。
  4. 加锁。对关键代码加锁。

内存屏障

std::memory_order是在内存屏障的基础上，进行的上层抽象设计。以使得多线程读写多个变量时，达到一定程度的可见顺序保证。包含 4 种类型：

  1. memory_order_relaxed：它只保证该变量本身的原子性，不保证解决多个变量之间的读写乱序。由于保证原子性，因此变量修改直达内存/cache。不会先读到寄存器，然后计算，最后写回内存。由于不解决多个变量之间的读写乱序问题，因此理论上不影响编译器指令重排。性能开销是最小的。
  2. memory_order_seq_cst：保证顺序一致。如果两个变量都使用 std::memory_order_seq_cst 进行读写，其中两个变量的写操作记为W1和W2。当任意线程的读操作观测到W1先于W2，那么其它线程的读操作也会观测到W1先于W2。在x86-64 CPU环境下，进行W1操作和W2操作后，都会立即清空Store Buffer，该操作本质上就是全局的数据同步，从而保证了顺序一致。是最强的顺序一致保证，也是c++原子变量的默认参数。但性能是最低的。
  3. memory_order_acquire 和 memory_order_release：对同一个变量进行两个操作：读操作R、写操作W。两个操作可以在同一个线程内，也可以在不同线程内。如果读操作R读取了写操作W写入的新值，那么R后续的所有其它变量的读操作，都能读取到W操作之前所有其它变量的写入值。
